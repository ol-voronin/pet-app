# 0009 — Хостинг API: свой сервер в Hetzner, Docker Compose и Caddy

- Статус: Принято (решение владельца 20.11.2026, issue #36)
- Дата: 2026-11-20

## Контекст
API нужен постоянный адрес с HTTPS, очередь (Redis для BullMQ) и место для воркеров распознавания и пушей.
Staging на Vercel Hobby бесплатный, но: только некоммерческое использование, нет долгоживущих процессов
(воркеры и очередь там не запустить), а особенности рантайма уже стоили нескольких кругов отладки (`docs/LESSONS.md`).
Ограничение владельца: ничего нового платного. У владельца есть оплаченный выделенный сервер в Hetzner Falkenstein.

## Варианты
1. **Свой сервер в Hetzner: Docker Compose + Caddy — выбрано.** Доплаты нет. Один образ API, тот же Node, что в CI.
   Caddy сам получает и продлевает сертификат. Redis рядом, наружу не открыт. Минусы: сервер один (нет
   отказоустойчивости), обновления ОС и Docker — на нас, на сервере могут жить другие проекты владельца.
2. **Остаться на Vercel.** Бесплатно, деплой из коробки. Не подходит: нет воркеров и очереди, Hobby — не для
   коммерческого продукта, а Pro платный.
3. **PaaS (Fly.io, Railway, Render).** Проще в обслуживании, но это новый счёт и банковская карта, а сервер
   уже оплачен. Цены на 20.11.2026 не сверялись — вариант отпал по ограничению «ничего нового платного».
4. **Kubernetes или Nomad на своём сервере.** Избыточно для одного сервиса и команды из одного человека.

## Решение
- **Образ:** `apps/api/Dockerfile`, две ступени: сборка (pnpm из `packageManager`, `--frozen-lockfile`, собранный
  `dist`) и рантайм (`node dist/index.js`, пользователь `node`, healthcheck на `/health`). Версия Node — из `.nvmrc`.
- **На сервере:** `deploy/docker-compose.yml` — API, Caddy (80/443, автоматический HTTPS), Redis (AOF, без вытеснения).
  База остаётся в Neon, файлы — в Neon Object Storage (ADR-0006).
- **Доставка:** `.github/workflows/deploy.yml` на каждый push в `main` собирает образ, проверяет, что контейнер
  стартует, и передаёт образ по SSH (`docker save | ssh docker load`). Реестр образов не нужен, секретов два:
  `SSH_HOST` и `SSH_KEY`. Пока их нет, workflow только собирает образ.
- **Секреты** — в `/opt/pet-app/.env` на сервере (права 600) и в секретах GitHub. В репозитории их нет.
- **Миграции** деплой не запускает: это ручной шаг (`CLAUDE.md`, «Не трогай без спроса» — продакшн-БД).
- **Vercel** остаётся запасным staging, пока сервер не проверен; потом — выключить.

## Последствия
- Появляются воркеры и очередь без новых счетов; следующий шаг на этом же сервере — Directus (issue #36, п. 5).
- Простой сервера = простой API. Приложение обязано переживать это: без сети медкарта читается из кэша (`docs/PRD.md`).
- Нужны: мониторинг доступности (бесплатный UptimeRobot или аналог), обновления ОС, бэкап `/opt/pet-app/.env`
  у владельца. Redis пока пуст; когда в нём появятся задачи — решить про бэкап тома.
- Перед публичным запуском: отдельное окружение `production` (сейчас сервер запускается как `staging`, потому что
  реальной доставки кода входа ещё нет), ветка Neon `main`, свой домен.

## Что проверено 20.11.2026
Образ собран и запущен локально: `docker compose up` (API + Caddy + Redis), `https://localhost/health` через Caddy,
вход с кодом `000000` и список питомцев на Neon `dev`, лимит тела запроса 1 МБ (413), остановка контейнера за 0,5 с.
На самом сервере не проверено: доступа к нему у Claude Code нет, первый деплой — после шагов владельца.

## Дополнение 20.11.2026: деплой «тягой» на сервере владельца
Секреты GitHub Actions владелец вставлять не стал, а Claude Code к ним доступа не имеет. Репозиторий публичный,
поэтому сервер обновляется сам: таймер systemd `pet-app-update.timer` раз в 5 минут запускает `deploy/update.sh`.
Тот забирает `main`, и если изменилось то, что крутится на сервере (`apps/api`, `packages`, `deploy`, lockfile,
`.nvmrc`), собирает образ на месте, перезапускает стек и ждёт `healthy`. Нездоровый образ откатывается на прошлый,
а этот коммит больше не пробуется, пока не придёт новый. Ключей и секретов нет. Цена — сборка (1–3 минуты CPU)
на общем сервере при изменениях API. Доставка по SSH из `deploy.yml` остаётся запасной: она включается секретами
`SSH_HOST` и `SSH_KEY`. Порты 80/443 на сервере держит Caddy другого проекта; наш API подключён к нему отдельным
блоком (метки `# >>> pet-app`), сам слушает только `127.0.0.1`.
