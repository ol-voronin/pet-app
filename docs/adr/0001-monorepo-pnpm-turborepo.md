# 0001 — Монорепо: pnpm workspaces + Turborepo

- Статус: Принято
- Дата: 2026-11-19

## Контекст
Мобильное приложение (Expo), API (Node) и позже B2B-кабинет (Next.js) делят zod-схемы, типы,
сгенерированный API-клиент и схему БД. Команда 2–3 человека, один репозиторий проще в поддержке.

## Варианты
1. **pnpm workspaces + Turborepo** — быстрые установки, строгие зависимости, кэш задач
   (typecheck/lint/test только для изменённых пакетов). Минус: Metro/Expo исторически капризен к
   симлинкам pnpm — проверяем на шаге Expo, при проблемах включаем `node-linker=hoisted`.
2. **Nx** — мощнее (генераторы, граф), но тяжелее в настройке и обучении; для 4 пакетов избыточен.
3. **Отдельные репозитории** — нет общего кода без публикации пакетов; рассинхрон схем.

## Решение
pnpm 12 + Turborepo 2. Структура: `apps/{mobile,api,web}`, `packages/{shared,db}`.
Общий `tsconfig.base.json` в корне (strict). Node ≥ 22 (`.nvmrc`).

TypeScript закреплён на **6.0.x**, а не 7.0: `typescript-eslint` 8.x поддерживает только `<6.1`.
Пересмотреть, когда typescript-eslint объявит поддержку TS 7.

## Последствия
- Корневые `pnpm typecheck|lint|test` идут через `turbo run` по всем пакетам.
- Фильтры `pnpm -F api|mobile|db|shared` работают по имени пакета (scope `@pet-app/` можно опускать).
