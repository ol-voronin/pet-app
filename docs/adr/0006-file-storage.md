# 0006 — Хранилище файлов: Neon Object Storage

- Статус: Предложено
- Дата: 2026-11-19
- Цены и лимиты проверены 2026-11-19 по документации вендоров (ссылки внизу). Перепроверить перед первым платным месяцем.

## Контекст
Файлы нужны с Этапа 1: фото и аватары питомцев, документы (сканы, PDF), позже — QR-паспорт и экспорт PDF.
Требования из `CLAUDE.md` и `docs/`:
- приватный бакет, доступ только по подписанным ссылкам с коротким сроком;
- хранение в ЕС (GDPR);
- файл до 20 МБ, типы `jpeg|png|heic|webp|pdf` (`docs/DATA_MODEL.md`);
- хранение файлов не ограничено лимитом сканов (объём растёт с числом пользователей);
- загрузка с телефона напрямую в хранилище по presigned URL;
- на старте расходы должны быть нулевыми или близкими к нулю (решение владельца 19.11).

Ожидаемый объём на старте: до нескольких ГБ (пилот — 3–5 клиник, сотни пользователей).

## Варианты

### 1. Neon Object Storage
S3-совместимое хранилище внутри проекта Neon. Проект `pet-app` уже в `aws-eu-central-1` (Франкфурт), регион поддерживается.
- **Цена:** $0.023/ГБ в месяц, за операции не берут. Исходящий трафик входит в общую квоту проекта (на Launch и Scale 500 ГБ в месяц, затем $0.10/ГБ). На Free — 5 ГБ хранилища. Для 10 ГБ это около $0.23 в месяц.
- **Плюсы:** новый аккаунт и секреты не нужны; хранилище ветвится вместе с БД (у `dev` свои файлы, `prod` не затрагивается); S3 API, подписанные ссылки до 7 дней (нам нужны минуты); объект до 5 ГиБ одним запросом.
- **Минусы и риски:** продукт молодой; реализована только часть S3 API; возможны ответы `503 SlowDown` (нужен повтор с паузой); файлы и БД у одного вендора; уровень доступа бакета (`private`) после создания не меняется; IP Allow и Private Networking хранилище не защищают, доступ держится только на ключах; восстановление БД из бэкапа (restore) файлы не откатывает, откатывает их только reset ветки. Сертификация GDPR у Neon указана для плана Scale — проверить, какой план у владельца, и что нужно для договора обработки данных.

### 2. Cloudflare R2
- **Цена:** бесплатно 10 ГБ-месяцев, 1 млн операций класса A и 10 млн класса B в месяц, исходящий трафик бесплатно. Дальше $0.015/ГБ в месяц, $4.50 за млн операций A, $0.36 за млн операций B.
- **Плюсы:** полностью бесплатно на старте; зрелый S3 API; нулевой egress.
- **Минусы и риски:** нужен ещё один аккаунт (и карта); нет веток — для `dev` и `prod` делаем разные бакеты и ключи вручную; ещё один вендор и набор секретов.

### 3. Hetzner Object Storage
- **Цена:** от €6.49 в месяц (без НДС): включены 1 ТБ хранения и 1 ТБ трафика; сверх — €0.0087 за ТБ-час хранения и €1.00 за ТБ трафика.
- **Плюсы:** ЕС (Германия/Финляндия), фиксированная цена, S3 API.
- **Минусы:** платно с первого дня, что противоречит решению «пока бесплатно»; нужен аккаунт; нет веток.

## Решение
**Neon Object Storage** для MVP.
- Приватный бакет `pet-files`, один на ветку Neon (`main` — продакшн, `dev` — разработка).
- Клиент — `@aws-sdk/client-s3` и `@aws-sdk/s3-request-presigner` (добавим вместе с модулем `storage`, в этой задаче зависимостей нет).
- Конфиг через переменные окружения (`S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`), без привязки к Neon: переезд на R2 или Hetzner — смена значений.
- Ключи объектов — `pets/<pet_id>/<uuid>.<ext>`; в БД хранится только `storage_key`, никогда не готовая ссылка.
- Ссылка на скачивание живёт минуты; на загрузку — до 5 минут, тип и размер проверяются при выдаче (и повторно после загрузки).
- Права: серверный ключ с записью; клиентские приложения ключей не получают.

Запасной вариант — Cloudflare R2: включаем, если счёт за хранилище вырастет или ограничения Neon Storage станут помехой (например, `SlowDown` под нагрузкой).

## Последствия
- Хранилище не бесплатно навсегда, но стоит копейки; стоит поставить уведомление о расходах в Neon (доступно на Launch и Scale).
- Дальше нужен модуль `apps/api/src/modules/storage` с тестами выдачи подписанных ссылок и проверкой типов и размера (следующий PR).
- Резервные копии файлов Neon отдельно не делает — нужен план (периодическая выгрузка в R2/Hetzner) до открытой беты. Это отдельная задача на Этапе 6.
- Документы остаются в приватном бакете (требование `CLAUDE.md`); публичные бакеты (`public_read`) не используем.
- Если решение принято, `CLAUDE.md`, `docs/ARCHITECTURE.md` и пункт про аккаунт Cloudflare R2 в Неделе 0 нужно обновить как уточнённые.
