# Roadmap

Отмечать `[x]` по мере выполнения. Один пункт ≈ одна сессия Claude Code ≈ один PR.

**Срок MVP: ≈ 21 неделя** (было 16). Пересчитан 19.11.2026 после решений из `docs/PRD.md`:
+0,5 нед. — загрузка файлов, +1 — произвольные напоминания и действия по типу,
+1 — свои метки и модерация, +2 — аватар (без учёта доводки 3D-форм художником),
+0,5 — запас на онбординг с двумя путями. Таб «События» убран из MVP (−0).

## Этап 1 — Аккаунт и питомцы (неделя 3–5)
- [ ] ADR-0006: хранилище файлов — Cloudflare R2 или Hetzner Object Storage (оба S3-совместимы)
- [ ] Auth: OTP (мок-провайдер в dev), JWT + refresh-сессии, SecureStore; способы входа в `auth_identities`
- [ ] Sign in with Apple / Google
- [ ] Онбординг «Добавьте питомца»: два равных пути — скан (заглушка до Этапа 3) или ручная форма; пропуск в один тап
- [ ] CRUD питомцев, фото через presigned URL, переключатель героя «аватар / фото»
- [ ] Семейный доступ: приглашение по ссылке (`pet_invites`), роли

## Этап 2 — Медкарта (неделя 6–9)
- [ ] ADR-0003: синхронизация — PowerSync (облако или self-hosted) или своя; с ценами
- [ ] Схема health_records + health_record_versions, API CRUD
- [ ] Экраны медкарты: таймлайн, фильтр по типам (вкл. «Документы»), карточка записи
- [ ] Кнопка «+»: только добавление — скан, файл, прививка, обработка, визит, анализ, лекарство, вес/заметка, напоминание
- [ ] Формы для каждого типа записи
- [ ] Загрузка файла как есть (фото, PDF): статус `stored`, лимит размера и типов, доступ офлайн после первой загрузки
- [ ] Офлайн по решению ADR-0003: локальная база, очередь изменений, разрешение конфликтов
- [ ] Справочники вакцин и препаратов (seed)

## Этап 3 — Скан и AI (неделя 10–12)
- [ ] ADR-0004: провайдер распознавания (Claude / Gemini / Document AI) — по eval на реальных документах
- [ ] Сканер документов, сжатие, загрузка, статусы
- [ ] Воркер OCR: LLM + JSON-схема, нормализация по справочникам
- [ ] Экран подтверждения: поля, confidence, увеличенный фрагмент оригинала
- [ ] Набор тестовых документов (20+ реальных фото ветпаспортов и справок) + eval-скрипт точности
- [ ] Лимит 5 сканов в месяц для Free (`scan_usage`, без блокировки истории; хранение файлов лимит не тратит)
- [ ] Распознавание уже загруженного файла по желанию (тратит скан)

## Этап 4 — Напоминания (неделя 13–14)
- [ ] Правила: ревакцинация, обработки, курс лекарств
- [ ] Произвольные напоминания: груминг, когти, корм, визит, своё — с повтором и временем заранее
- [ ] Действие по типу: «нужен специалист» → «Записаться» (звонок / место на карте → дата записи → перенос) + «Уже сделано»; дома → «Сделано»
- [ ] Локальные уведомления + серверные пуши (`devices`), «отложить»
- [ ] Запрос разрешения на пуши в момент ценности

## Этап 5 — Карта (неделя 15–17)
- [ ] ADR-0005: MapLibre + MapTiler или Mapbox
- [ ] Импорт OSM (клиники, аптеки, площадки), скрипт обновления; Харьков — с ручной проверкой
- [ ] Ручная проверка: админка (Directus) для правки точек
- [ ] Гео-API / векторные тайлы, кластеры, фильтры, шторка, карточка точки, звонок из карточки; тёмные пины
- [ ] Свои метки: личные (владелец + семья, сразу) и публичные (после модерации); очередь модерации в админке

## Этап 5b — Аватар питомца (неделя 18–19)
- [ ] ADR-0007: рендер аватара — в приложении или готовой картинкой с сервера
- [ ] Параметры аватара (`pets.avatar`), автосборка по виду и породе
- [ ] Конструктор: уши, морда, шерсть, окрас; собака и кошка
- [ ] Пайплайн рендера (по ADR-0007) на основе `tools/avatar/balloon_pets.py`; ракурс три четверти

- [ ] Пилот: 3–5 клиник Харькова, QR-стикеры
