# Как начать работу в Claude Code

## 0. До первой сессии (делаете вы, ~1 день)
- [ ] Создать пустой приватный репозиторий на GitHub (например, `pet-app`), склонировать локально.
- [ ] Скопировать в корень репозитория содержимое этого набора: `CLAUDE.md`, `docs/`, `.claude/`, `START_HERE.md`.
- [ ] Установить: Node LTS, pnpm, Git, Claude Code (`npm i -g @anthropic-ai/claude-code`), EAS CLI (`npm i -g eas-cli`), Xcode (если есть Mac) и/или Android Studio с эмулятором.
- [ ] Аккаунты: Expo, Apple Developer ($99/год), Google Play Console ($25 разово), Neon, Cloudflare (R2), Upstash, Sentry, PostHog.
- [ ] Подключить MCP-серверы в Claude Code: GitHub, Neon, Vercel, Figma, Sentry. Для актуальной документации библиотек — Context7.
- [ ] В Figma — 5–7 ключевых экранов MVP: онбординг со сканом, экран подтверждения OCR, медкарта, питомец, карта. Хотя бы вайрфреймы.

## 1. Сессия «Фундамент»
Запустить `claude` в корне репозитория, нажать Shift+Tab до режима Plan и отправить:

> Прочитай CLAUDE.md и всё в docs/. Это новый проект, кода ещё нет.
> 1) Задай мне до 10 вопросов, где документы противоречат друг другу или чего-то не хватает.
> 2) Затем составь план Этапа 0 из docs/ROADMAP.md: структура монорепо, версии ключевых пакетов (проверь актуальные, не по памяти), порядок шагов.
> Пока ничего не создавай.

Ответить на вопросы → одобрить план → дальше `/feature` по пунктам Этапа 0.

## 2. Сессия «Решения» (параллельно с Этапом 0)
> /adr Fastify vs NestJS для API — учти, что команда 2–3 человека и нужен OpenAPI
> /adr PowerSync vs своя синхронизация для офлайн-медкарты на Expo + Neon
> /adr Провайдер распознавания: Claude vs Gemini vs Google Document AI для украинских ветдокументов — цена за документ, точность, JSON-схема
> /adr MapLibre + MapTiler vs Mapbox для React Native

Каждое решение — прочитать, подтвердить или поправить, потом статус «Принято».

## 3. Ежедневный цикл
1. `claude` → `/feature` (или `/feature <пункт>`).
2. Читаете план, отвечаете на вопросы, пишете «ок».
3. Claude реализует, сам гоняет проверки, открывает PR.
4. `/review` → критичное исправлено → вы проверяете на телефоне (development build) → merge.
5. `/clear` перед следующей задачей — чистый контекст на каждую фичу.

## 4. Как ставить задачи по дизайну
- Дайте ссылку на фрейм Figma: «Сверстай этот экран по фрейму <ссылка>, используя компоненты из src/shared/ui. Если компонента нет — сначала добавь его в дизайн-систему».
- Скриншот или фото эскиза тоже подойдёт: перетащите картинку в терминал.

## 5. Правила, которые экономят время
- Одна фича за сессию. Длинные сессии теряют фокус — лучше `/clear` и новая задача.
- Если Claude дважды ошибся в одном месте — остановите, `Esc`, объясните иначе или дайте пример.
- Повторяющуюся поправку («не используй X», «тексты всегда через i18n») добавляйте в CLAUDE.md, а не повторяйте в чате.
- Ничего не пушьте в main напрямую. Всё через PR — так у вас есть история и откат.
- Раз в неделю: «Сверь ROADMAP с фактическим кодом и предложи, что убрать или упростить».

## 6. Где нужен человек, а не Claude Code
- Юрист: публичная оферта, политика конфиденциальности, агентская схема для билетов (V2).
- Сбор 20+ реальных ветдокументов для проверки OCR (знакомые владельцы, клиники).
- Переговоры с клиниками для пилота и ручная проверка точек на карте.
- Финальная проверка на реальных устройствах, особенно бюджетных Android.
